Servicios Backend

📡 MQTT Service
services/mqtt_service.py
Cliente MQTT (paho). Recibe datos de los dispositivos físicos por tópicos. Llama a signal_processor para ECG y hace broadcast al WebSocket manager.
🔌 WebSocket Manager
services/websocket_manager.py
Gestiona todas las conexiones WebSocket activas. Broadcast de mensajes a todos los clientes conectados en tiempo real.
🫀 Signal Processor
services/signal_processor.py
Filtros de señal ECG en tiempo real (ecg_filter_realtime). Normalización y limpieza de la señal antes de enviarse al frontend.
🔐 Auth Service
services/auth_service.py
Generación y validación de tokens JWT. Hashing de contraseñas. Dependencia inyectable para rutas protegidas.

Flujo de Datos

📡 Tiempo Real (Sensores → Frontend)
1. Dispositivo físico publica en MQTT Broker (tópico por sensor)
2. mqtt_service.py recibe mensaje → signal_processor filtra ECG
3. ws_manager.broadcast(msg) → envía a todos los WebSocket conectados
4. app.js / detalle.html / monitorU1.html reciben y filtran por Uid_Equipo
5. UI actualiza cards, gráficos uPlot y valores numéricos
🔔 Ciclo de Vida de una Alarma
1. signal_processor detecta valor fuera del rango_signo_vital del paciente
2. POST /alertas/ → crea alerta con estado = ACTIVA
3. app.js consulta GET /alertas/?estado=ACTIVA → marca card del panel con badge rojo
4. Médico visualiza en admin/alarmas.html → una card por paciente, última alerta por sensor
5. PATCH /alertas/resolver/paciente/{id} → estado = RESUELTA + resuelta_en = now()
🔗 Vinculación Paciente ↔ Dispositivo
1. PATCH /dispositivos/{id} con id_paciente → inserta fila en paciente_dispositivo con fecha_hora_asoc
2. GET /pacientes_por_dispositivo_uid/{uid} → busca paciente_dispositivo donde fecha_hora_disoc = NULL
3. Para desvincular: PATCH actualiza fecha_hora_disoc = now() en el registro anterior
4. GET /dispositivos/ devuelve id_paciente activo (el de la asociación activa)
